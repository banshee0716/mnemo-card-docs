# product-docs slice 2 — intent

Owner G1 裁定草稿，2026-10-14。slice 1（文件站首版）已於 2026-10-14 RELEASED；本切片只改一篇文章。

## 使用者得到什麼

讀者打開〈認識 mnemo-study-cards〉，讀到的是這個技能**怎麼做決策**：拿到一份來源後，它如何判斷知識主題與
牌組、如何拆分內容、如何生成卡片，以及哪些事會問使用者、哪些自己決定、怎麼檢查結果。內容完全以技能
v0.2.0 的實際規則為準，用一般讀者看得懂的話說明，不寫成技術文件。

## owner 裁定（G1，2026-10-14）

1. **範圍**：只重寫第二篇〈認識 mnemo-study-cards〉。標題與網址不變（側欄、上下篇、其他頁的連結都不動）；
   頁面說明（description）可隨新內容調整。首頁卡片說明若與新內容不符，同步改一句。
2. **架構**：依 owner 列的三個問題組織。開頭一小段帶過技能的五個階段（盤點、定案、撰寫、檢查、交付），
   主體依序是：怎麼判斷主題與牌組 → 怎麼拆分內容 → 怎麼生成卡片（四種卡型、正面與背面、冷讀），
   再加「哪些事會問你」與「怎麼檢查」。
3. **卡型名稱**：用中文名稱（基礎概念卡、深入解析卡、關聯整合卡、範例應用卡）與各自回答的問題，
   不寫英文代碼。名稱須先對照 Mnemo-Card 主程式現況核對；與產品顯示不一致時停下問 owner。
4. **範例**：沿用〈Cognitive offloading〉，與第三篇一致；標明是示意，不是實際產卡結果。
5. **舊段落**：濃縮保留——來源依據併入「怎麼生成卡片」；三層檢查表保留在「怎麼檢查」；
   「拿到卡包後」縮成一句並連到第三篇。
6. **兩篇分工**：第二篇只說明原理（技能如何決策），不寫操作步驟、不需要讀者照做；第三篇〈安裝並第一次產卡〉
   是單純的步驟說明，**不讀第二篇也要能照著做出卡片**。第三篇目前沒有引用第二篇；本切片不改第三篇，
   但由核對者單獨讀第三篇確認足以完成產卡；若發現缺口，停下問 owner（改第三篇屬範圍變更）。
8. **第三篇補充**（owner 2026-10-14，看過 S5 結果後裁定）：第三篇大致沒有問題，只補「卡包與檢查結果怎麼讀」；
   第 1 節「目前尚未開放下載」改成一句說明技能是什麼（不點名 AI 工具），並寫明技能檔由研究者提供給符合條件的受試者。
   S5 其餘缺口不處理，列為已知限制。
7. **不做**：「編輯此頁」連結（owner 改在 GitHub 網頁直接編輯）、保護 main、PR 流程、工作流加跑公開檢查。

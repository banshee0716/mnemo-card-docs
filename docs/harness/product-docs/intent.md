# product-docs — intent

Owner G1 裁定，2026-10-14。完整的方案比較與挑戰紀錄留在 Mnemo-Card 主程式儲存庫作為內部紀錄；
本檔只寫文件站本身。

## 使用者得到什麼

受邀使用 Mnemo-Card 的受試者，從公開文件站讀到三篇繁中文章，能自己完成第一次登入與第一輪練習，
並知道 mnemo-study-cards 技能是什麼、怎麼用它產卡並匯入；學術或作品集讀者讀得懂同一套內容。
文件站有側欄、文章目錄、上下篇與中文搜尋，手機也好讀；文章裡寫的每個產品操作都能在正式產品上照做。
文件站與 Mnemo-Card 主程式各自建置、各自發布。

## owner 裁定（G1，2026-10-14）

1. **架構**：本公開儲存庫，Astro + Starlight 靜態建置，GitHub Actions 部署到 GitHub Pages。
   不使用 SSR、後端、資料庫或第三方搜尋服務；不與 Mnemo-Card 主程式共用建置或部署。
2. **網址**：首版用 GitHub Pages 專案站 `https://banshee0716.github.io/mnemo-card-docs/`
   （Astro `site` 與 `base: '/mnemo-card-docs'`）。買網域後再換 `docs.<網域>`，接受連結變動一次
   （GitHub 官方文件未記載專案站換自訂網域後舊網址會轉址）。讀者主要是學界，不大量對外散布。
3. **讀者**：以受邀受試者為主（目標：完成第一輪練習），學術或作品集讀者也看得懂。
4. **首版篇目**：文件首頁＋三篇——「第一次使用 Mnemo-Card」「認識 mnemo-study-cards」
   「安裝並第一次產卡」。另兩篇（複習與排程、匯入卡包）之後再想；不建空頁或空分類。
5. **註冊**：第一篇以一句話帶過「目前暫不開放註冊」，主線從登入開始。
6. **第三篇**：寫成流程說明——準備論文與學習目標→提出產卡要求→檢查產出→匯入 Mnemo-Card→
   開始學習。「下載與安裝」只寫目前尚未開放下載；不放示範產物，細節之後再補。
   不提供猜測的下載連結、指令、版本或安裝路徑。技能說明以 v0.2.0 為準。
7. **公開儲存庫**：接受。見 `AGENTS.md` 的公開規則。
8. **審查**：LOW 輕量流程（見 `AGENTS.md` 工作方式 3），Codex 在本儲存庫內審查。
9. **治理**：本切片的 harness 文件在本儲存庫；之後的工作階段直接在這裡開。

## 範圍

- Astro + Starlight 專案；單一語言根語系（繁體中文，台灣）；品牌樣式（CSS 變數、Noto Sans TC／
  Noto Serif TC、Logo）；側欄；文件首頁與三篇 MDX；Pagefind 搜尋（Starlight 內建）。
- 返回產品：以絕對網址連到 `https://mnemo-card.vercel.app/app`（未登入者由產品導去登入頁）與
  產品首頁 `https://mnemo-card.vercel.app/`。
- GitHub Actions 部署工作流；建置後檢查（頁面、站內連結、搜尋、手機寬度、鍵盤、無障礙）。

## 非目標

- Mnemo-Card 主程式的任何改動。首頁加「文件」入口是主程式另一個切片，等本站網址上線後才做。
- 自訂網域與 DNS（等買網域）；預覽環境；多語；版本切換；內容管理系統；留言或回饋功能；
  編輯此頁連結；技能下載包與安裝步驟；第三篇的示範產物。

## 品質線

- 文章描述的每個產品操作必須能在正式產品上照做，由全新工作階段的子代理逐步對照主程式現況核對，
  作者不自驗。不宣稱學習效果。
- 手機 375px 無非預期橫向捲動；只用鍵盤能操作跳到正文、側欄、文章目錄、搜尋與手機選單；
  介面文字是繁體中文。
- 用文章中的真實中文詞（例如「熟悉度」「牌組」「卡包」）搜尋，能找到對應文章。
- 建置產物沒有失效的站內連結、圖片或資源路徑（含 `base` 前綴）。

## 規模數字

- 篇數：首版 3 篇＋文件首頁；之後至少再加 2 篇。
- 更新頻率：低，依需要更新。
- 託管上限（GitHub Pages 官方限制頁，2026-10-14 查）：網站 ≤ 1 GB；流量軟上限每月 100 GB；
  部署逾時 10 分鐘；每小時 10 次建置的軟上限不適用於自訂 Actions 工作流。三篇文字站遠低於上限。
- 用途限制：GitHub Pages 不得作為商業交易或商業 SaaS 網站；本站是非商業的產品說明文件，
  若日後商業化需重新檢查。

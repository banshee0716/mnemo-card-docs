## 1. 需求

- **R15 第二篇的目的與結構**：〈認識 mnemo-study-cards〉說明技能 v0.2.0 **怎麼做決策**，不教操作。
  標題「認識 mnemo-study-cards」與網址 `skills/mnemo-study-cards/` 不變；`description` 改成符合新內容。
  1. 開頭：技能做什麼（一段），以及五個階段的概觀（盤點、定案、撰寫、檢查、交付，一小段或一個短清單，
     不另立 h2）。點明「技能協助準備材料；理解、回想與解釋仍要學習者自己練習」。
  2. 主體段落（h2）依序為下列五個主題，最後是「下一步」，共六個 h2，不夾其他 h2。標題文字在文案階段定稿，
     順序與涵蓋範圍不變（G2 F6）：
     1. **怎麼判斷主題與牌組**：先把來源切成單元並列出候選學習目標；一副牌組只處理一個主題
        （一個單元，或符合合併條件的相鄰單元）；先備概念先定；太大就拆成多副；副數的預設與使用者指定副數時的處理。
        拆成多副（以及技能規定要列摘要的其他情況）時，先列出計畫摘要，**然後直接開始寫卡、不等確認**；
        只有使用者在要求中說要先看計畫，才停下等回覆（G2 F3）。
     2. **怎麼拆分內容**：一張卡練一個能獨立完成的目標；寧可少拆，只有目標各自可獨立檢驗、為學習目標所需、
        彼此不重複時才拆；不因來源提到某個名詞就拆；碎片要合併、太粗要拆開；不為湊張數灌水。
     3. **怎麼生成卡片**：四種卡型（見 R16），依來源能回答的問題選型，來源撐不起的卡型不做、不湊滿四型；
        正面帶齊一個目標所需的知識，並通過冷讀：以這副牌設定的先備程度為準，沒讀過來源、也沒看過同副其他卡的
        讀者，只看這張正面也讀得懂，領域常識不另解釋（G2 F4）；背面有一段概述與兩個提示，一個回想、一個用自己的話
        解釋，背面組成以產品畫面為準（G2 F1）；每張卡要講出「為什麼／怎麼運作」；學習者看到的文字不指涉來源文件；
        每個實質說法要有來源依據，推論與外部補充要標明（濃縮自 slice 1 的「來源依據」段，不另立 h2）。
     4. **哪些事會問你**：決定分三種——來源查得到的事實不問、只有少數學習設計問題可能問使用者、其餘自己決定；
        可能問的只有四件事（範圍、程度基準、裝不下時的取捨、來源沒有但要保留的詞），另外兩種情況會停下：
        來源讀不到或缺漏時請你補件、你要求先看計畫時等你回覆（G2 F3）；什麼情況才問、每題附推薦答案、
        回「照推薦」即全部採用、每輪題數上限；多數情況不問或只問一輪、最多三輪，不問也是正常結果（G2 F3）；
        沒有人能回覆時採用推薦答案並在交付時列為假設；與來源衝突時以來源為準並交代未涵蓋的部分。
     5. **怎麼檢查**：先由程式檢查結構，再逐卡、逐副審查內容；結構通過不代表內容正確；修正次數有上限；
        結果可能是通過、受阻或未驗證（用一般說法，不寫狀態代碼）。保留 slice 1 的三層檢查表
        （結構正確性、內容合理性、學習有效性）。
  3. 文末「下一步」：一句說明拿到卡包後的事由第三篇說明，連到〈安裝並第一次產卡〉；另連〈第一次使用 Mnemo-Card〉。
     全文至少一處使用「卡包」一詞（AC5 搜尋詞，G2 F2）。
  4. 範例：沿用 Risko 與 Gilbert（2016）〈Cognitive offloading〉，標明是示意、不是實際產卡結果；
     不放產好的卡片、牌組數或卡片數。論文內容一律轉述（同 R11）。
  5. **不寫操作步驟**：不寫輸入什麼、按哪個按鈕、選哪個檔案、執行什麼指令。描述技能如何回應
     （例如收到「照推薦」就全部採用）屬於決策說明，不算操作步驟；但不寫成「請輸入／請回覆…」的指示句（G2 F8）。
  6. **不寫實作細節**：不寫檔名（含 `pack.md`）、程式指令、腳本、JSON 欄位、英文卡型代碼、
     變數代號（L1–L4）、結果狀態代碼（`PASS`、`BLOCKED` 等）或審查項目的內部名稱。頁面 `description` 同樣適用。
     技能規則中的數字（例如每輪最多幾題、一副的目標上限）可以寫，須與技能原文一致。
  7. 不宣稱學習效果（同 slice 1）。
